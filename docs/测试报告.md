阶段分析：
- 商品阶段吞吐约 5 秒/条（2 worker 并发），100 条商品页 13 分钟内全部处理完

- 拦截率超阈值后协调器主动收尾，剩余 40 条标 cancelled，避免继续冲击被更狠封禁

## 四·补 · 重跑验证（canary 保护 + 评论开关价值）

两次重跑（批次 `073ab419` 14:07、批次 `6c889cfe` 14:35，均为 52 条 = 40 cancelled + 12 blocked，评论采集**关**）：

| 指标 | 数值 |
|------|------|
| 两次结果 | canary 探针均 2/2 被 captcha 拦截 → 批次未放开全量，17 秒收尾 |
| 请求数 | 两次合计仅 4 条探针请求（104 条成员没有冲出去） |
| 收尾类别 | blocked |
| 结论 | canary 保护在 IP 被临时限流时正确生效，最大限度省流量；反爬冷却（通常数小时）后重新上传清单即可补采，属日常操作 |

进度日志：`docs/evidence_formal_100.log`、`docs/evidence_retry_52.log`

## 五、已知限制

1. **关键词排名不支持**：本系统只做 ASIN 商品详情/评论/BSR，关键词排名明确拒绝
2. **评论页登录墙**：亚马逊限制未登录浏览评论，属常态——商品数据正常入库，成员仍算成功，评论汇总标 login_wall
3. **限速是硬约束**：亚马逊反爬决定吞吐上限，5800 量级批次耗时以天计，属预期
4. **变体跳转**：跳到默认变体的成员标 variant，不算原商品成功（数据里保留实际 ASIN）
