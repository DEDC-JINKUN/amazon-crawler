# 代理流量与采集成本验证

本文档用于回答“200 元能否获得千万级数据”。验证时不把页面、ASIN、表记录和字段值混为同一个“数据量”，代理商后台的计费流量是成本真值。

## 先确定“一条数据”

汇报时必须同时给出下列四个口径，不得只报其中一个：

| 口径 | 例子 | 用途 |
|---|---|---|
| 请求/页面数 | 1 个商品页、3 个评论页 | 衡量站点访问压力 |
| 成功 ASIN 快照数 | 一个 ASIN 完成一次商品采集 | 衡量业务覆盖 |
| 标准化表记录数 | 商品、媒体、A+、评论各表行 | 衡量数据库产出 |
| 非空字段值数 | 标题、价格、评分等每个值 | 只有老板所说的“千万级”明确指该口径时才使用 |

“1 个页面解析出 100 个字段值”是 1 次页面请求和 100 个业务数据，不是 100 次抓取。

## 当前可用的本地基线

可复现批次 `run-20260827T103522709917Z` 有 10 个 HTTP 2xx 页面，其中 9 个 ASIN 通过商品页校验，1 个因 ASIN 不一致不算成功。对重用同一源文件的重复 evidence 去重后，保存响应体共 15,543,610 bytes（15.54 MB / 14.82 MiB），平均 1.647 MiB/成功 ASIN。按 5,800 个 ASIN 每个只取一个商品页线性估算，一次全量的未压缩 HTML 约为 9.33 GiB。

这只是保存的响应体，不是代理账单；它没有完整包含请求头、TLS/代理协议开销、失败重试、评论分页和 Firefox 加载的子资源。

## 真实测试方法

### 1. 样本与分组

先用 100 个 ASIN 做校准，然后用 500–1,000 个 ASIN 做成本估算。样本要包含不同类目、有货/无货、单变体/多变体、有/无 A+ 和评论量高/低的页面。

| 组 | 采集内容 | 目的 |
|---|---|---|
| A | HTTP 商品页 | 确认主路径最低成本 |
| B | HTTP 商品页 + 固定数量评论页 | 量化评论增量 |
| C | 只处理需要 Firefox 降级的页面 | 量化浏览器额外流量 |

三组使用同一出口产品、国家/州、ZIP、限速、时间窗口和价格，不在一次测试中更换供应商或线路类型。

HTTP 组内再分为 gzip 和 identity 两组，只更改 `http_accept_encoding`。两组的解析结果、成功 ASIN 和失败分类必须一致；以 evidence 的 `transfer_bytes` 和代理后台差值判定压缩是否值得作为默认。

### 2. 记录代理账单差值

1. 新建独立测试批次和输出目录，避免混入旧 HTML。
2. 在代理商后台记录开始累计流量 `U0` 和费用 `C0`，同时保存截图、时间和供应商的 GB/GiB 定义。
3. 运行固定批次，中途不运行其他共用该代理账号的任务。
4. 等代理商计量后台更新，记录结束累计流量 `U1` 和费用 `C1`。
5. 真实计费流量是 `U1 - U0`，优先通过用量 API 或供应商单位定义转换为 bytes。优先使用实际费用差 `C1 - C0`；如果只有单价，计算结果只是可变流量成本。月租、最低消费、阶梯价、超额价和税费必须记录或分摊，不用本地网卡统计代替账单。

### 3. 生成采集指标和成本报告

先取得本次 `run_id`，再执行：

```powershell
.venv\Scripts\python.exe scripts\traffic_cost_report.py `
  --db state\traffic_test.sqlite3 `
  --raw-html-dir data\traffic_test\raw_html `
  --run-id <run_id> `
  --proxy-usage-before-bytes 10000000000 `
  --proxy-usage-after-bytes 10235000000 `
  --proxy-charge-cny 1.20 `
  --allocated-fixed-cost-cny 0.10 `
  --target-asins 5800 `
  --budget-cny 200
```

工具统一接收 bytes，避免把供应商的 GB 误当成 GiB。`--proxy-charge-cny` 是本批实际费用差，优先于扁平单价；如果暂时没有费用差，才使用 `--proxy-price-cny-per-gb`。如果要报“元/百万条数据”，必须先写清业务数据的定义，再增加 `--business-units <本批数量>`。

## 必须汇报的结果

- 成功 ASIN 数和成功率；成功 ASIN 必须是本批商品 `/dp/{ASIN}` 页面通过 ASIN、上下文和核心字段校验，仅评论页 200 不算；
- HTTP 页、评论页、Firefox 页和重试请求数；
- 代理计费 GB、GB/千个成功 ASIN、元/成功 ASIN；
- 实际与保存 HTML 体积的比率；
- 5,800 个 ASIN 一轮的预测流量和代理费；
- 如果定义了业务数据单位，报告元/百万单位；
- 403、429、CAPTCHA、空页、ASIN 不一致和浏览器降级率。

## 通过标准

“200 元千万级”不作为无定义的硬指标。验收时必须同时满足：

1. “一条数据”的定义固定，且可从输出表重算；
2. 代理流量来自后台差值或用量 API，不是仅看本地 HTML 大小；
3. 成功率、字段完整率和阻断率同时达标，不用大量失败请求凑流量；
4. 500–1,000 条生产型样本的线性外推与第二批实测误差不超过 20%。

HTTP 压缩、评论页上限、浏览器子资源策略和重试比例应通过 A/B 实测决定，不在没有代理账单证据时宣称已达到目标。
