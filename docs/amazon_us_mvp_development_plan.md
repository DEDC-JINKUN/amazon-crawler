# Amazon 美国站商品数据采集 MVP 一周开发计划

> 版本：v0.1
> 计划日期：2026-08-27
> 开发模式：单人开发
> 一周目标：上线可受控运行的采集 MVP，不承诺一周内完成 3,800–5,800 个 ASIN 的全量生产采集。

## 1. 开发目标

为多个 Agent 建立统一的 Amazon.com 商品数据采集能力，先完成真实页面采集核心，再接入最小查询 API，最后评估 Weknora 写入和浏览器 Skill 固化。

目标数据范围：

- 自有 ASIN：不超过 800 个；
- 竞品 ASIN：约 3,000–5,000 个；
- 首周只使用已审核的小批量 ASIN 做上线验收；
- 竞品通过关键词、类目和相关商品发现后，必须由运营确认归属。

### 1.1 会议已确认的方向

- 一周内先上线可受控运行的核心采集能力，不以一周完成 3,800–5,800 个 ASIN 全量刷新为目标；
- 代理采用付费方案，GitHub 免费代理池只参考接口思路，不作为生产出口；
- 开发顺序为：核心爬虫和异常处理 → 最小查询 API → 再评估 Weknora 和浏览器 Skill；
- 页面采集以公开页面实际显示内容为边界，先保证原始页面和结构化结果可追溯。

需要补齐的输入是：付费代理供应商、预算、代理凭证、首轮测试 ASIN 和美国 ZIP/配送上下文。

## 2. “一周上线”的定义

本计划中的上线是指：

- 采集服务可以在授权环境中顺序采集小批量商品页；
- HTTP 优先，字段不足时使用 Firefox 兜底；
- 原始页面证据、结构化字段和任务状态可以保存；
- 任务中断后可以从断点继续；
- 403、429、验证码、登录墙和页面异常不会覆盖有效数据；
- 付费 IP 代理可以通过统一配置接入，出现阻断时能暂停和受控切换；
- Agent 可以通过最小 API 查询最新快照和任务状态。

以下内容不作为首周上线承诺：

- 3,800–5,800 个 ASIN 的全量日常刷新；
- 全量历史评论和所有媒体二进制下载；
- 多家代理供应商同时接入和自动竞价；
- 多账号自动注册、自动换号或验证码处理；
- Weknora 的完整知识运营和复杂问答编排。

## 3. 优先级和技术路线

### P0：必须完成

1. ASIN 清单和任务状态；
2. HTTP 商品页采集；
3. Firefox 动态页面兜底；
4. 页面解析、字段标准化和质量门禁；
5. 原始 HTML/DOM 证据和采集时间；
6. 断点、重试、失败队列；
7. 一家付费美国住宅/ISP 代理的接入；
8. 403/429/挑战页暂停和有限备用出口切换；
9. 小批量真实 Amazon 验收。

### P1：P0稳定后完成（首周只交付最小版）

1. 最小 Collection API；
2. 按 ASIN 查询当前快照；
3. 查询任务状态；
4. 查询最近采集证据；
5. 提交按需刷新请求。

历史变化查询放到核心采集稳定后的下一阶段，避免挤占一周核心爬虫开发时间。按需刷新只负责入队，不在 API 请求线程中直接运行爬虫。

### P2：首周之后评估

1. PostgreSQL 替换或承接 SQLite；
2. 多 Worker 并发扩展；
3. Weknora 商品档案和变化摘要发布；
4. 浏览器操作固化为 Skill；
5. 竞品批量扩展至 3,000–5,000 个 ASIN。

## 4. 目标架构

```text
自有/竞品 ASIN 清单
        ↓
ASIN 主数据和任务状态
        ↓
任务调度、缓存、新鲜度判断
        ↓
付费 IP 代理出口 + 全局限速
        ↓
HTTP Worker
        ↓ 页面字段不足
Firefox Worker
        ↓
解析与字段标准化
        ↓
质量门禁
        ├─ 通过：当前快照、历史、原始证据
        └─ 失败：保留旧值、重试或人工队列
        ↓
SQLite（MVP）/ PostgreSQL（生产）
        ↓
Collection API（P1）
        ↓
多个 Agent
```

Weknora 不参与 P0 采集闭环。P0 先保证事实数据和证据可用，P2 再将经过质量校验的快照转换为商品档案和变化摘要。

## 5. 一周日程

### 第 1 天：冻结需求和环境

交付：

- 确认 20–50 个首轮测试 ASIN，其中自有和竞品归属明确；
- 确认页面字段清单、刷新频率和美国访问上下文；
- 按陈总已确认的方向选择一家付费代理供应商，确认美国出口、HTTP(S)、认证方式、预算和使用条款；不在本阶段开发供应商专用逻辑；
- 准备 Python、Firefox、Selenium 和代理凭证的安全配置；
- 冻结验收指标和失败处理规则。

必须补齐：

- 代理供应商、预算和凭证交付时间；
- 是否允许采集评论正文；
- 统一的美国 ZIP/配送上下文；
- 首轮 20–50 个已确认 ASIN。

“一周上线”已经确定为核心采集小批量可运行，不再作为待拍板事项。

### 第 2 天：跑通 HTTP 主链路

交付：

- HTTP 请求和超时处理；
- 透明 User-Agent；
- 200、403、429、5xx 和挑战页分类；
- 商品页原始 HTML 保存或内容哈希；
- HTTP 页面解析标题、品牌、价格、可售状态、评分、评论数和 Canonical；
- 失败结果不得覆盖上一次有效快照。

验收：使用本地 fixture 和少量真实页面，能够完成一次完整的请求—解析—落库流程。

### 第 3 天：Firefox 兜底和全字段整理

交付：

- HTTP 缺少核心字段时才启动 Firefox；
- 使用独立临时 Profile；
- 读取渲染后的 DOM；
- 解析 Bullets、描述、规格、Offer、卖家、变体、A+ 和媒体 URL；
- 对页面显示但暂未识别的模块保留原始片段或 `extra_fields`；
- 记录页面语言、配送地区和区域上下文。

验收：静态页面走 HTTP，动态页面能够自动降级到 Firefox，并且来源类型可追溯。

### 第 4 天：断点、异常和付费代理接入

交付：

- 任务状态、租约、重试次数和下次重试时间；
- 进程中断后可以继续未完成任务；
- 接入一家付费代理的 HTTP/HTTPS 出口；
- 每个出口独立限速和健康记录；
- 403/429/挑战页触发暂停和冷却；
- 只允许一次受控备用出口切换；
- 备用出口也失败时停止新增任务并转人工。

验收：通过故障注入验证 403、429、网络超时、空页面、ASIN 不匹配和进程中断，不主动制造 Amazon 封禁。

### 第 5 天：真实小批量采集

交付：

- 顺序采集 20–50 个已审核 ASIN；
- 至少包含有货和无货商品；
- 至少包含自有和竞品商品；
- 记录成功率、字段完整率、HTTP→Firefox 降级率、延迟、流量、403/429/挑战页和失败原因；
- 输出真实采集报告和失败 ASIN 清单。

验收：所有成功记录必须通过 ASIN/Canonical 校验，价格为空时必须能区分无货、页面未显示和解析失败。

### 第 6 天：最小 Collection API

交付：

```http
GET  /v1/asin/US/{asin}
GET  /v1/jobs/status
GET  /v1/asin/US/{asin}/evidence
POST /v1/asin/US/{asin}/refresh
```

要求：

- API 不直接暴露代理凭证、浏览器会话或内部数据库连接；
- 返回值包含 `captured_at`、`freshness`、`source` 和 `quality_status`；
- 数据未达到新鲜度要求时，Agent 可提交刷新请求，但只能入队，不直接操作爬虫；
- API 错误不影响采集任务继续运行。

历史查询和任务详情接口列入下一阶段，不影响首周核心上线；按需刷新只负责入队。

### 第 7 天：上线验收和交接

交付：

- 一次完整的定时采集演示；
- 一次中断后断点恢复演示；
- 一次 403/429 模拟处置演示；
- 真实小批量指标报告；
- 运行配置、部署说明、故障处理说明；
- 明确下一阶段扩容和 Weknora 是否启动。

上线判定：P0 全部通过，P1 完成当前快照、任务状态和最近证据查询；P0 任一硬门禁未通过，则只能称为 POC，不称为生产上线。

## 7. 验收指标

### 7.1 结构验收

- 成功记录的 ASIN 与目标 URL/Canonical 一致；
- 商品页、评论页、媒体和内容模块的主键不重复；
- 任务状态与状态历史一致；
- 进程中断后能继续未完成任务；
- 失败页面不会覆盖上一条有效快照。

### 7.2 真实采集指标

首轮只记录事实，不预设 Amazon 的“安全请求数”：

- 商品页成功率；
- 核心字段完整率；
- HTTP→Firefox 降级比例；
- 价格/卖家/Buy Box 可见率；
- 403、429、验证码和登录墙比例；
- 单页耗时和总流量；
- IP 代理出口可用率；
- 阻断后的恢复时间；
- 评论详情页可访问率。

### 7.3 硬失败条件

- 把挑战页当成商品页保存；
- ASIN 不一致仍写入当前快照；
- 使用个人 Cookie、Token 或账号；
- 自动破解验证码或无限轮换 IP/账号；
- 没有断点，失败后只能全量重跑；
- 没有记录页面上下文却把区域价格当成美国统一价格。

## 9. 当前明确决策

- 生产方向使用付费美国住宅/ISP代理，不使用 GitHub 免费开放代理作为生产出口；
- 当前 POC 保持低并发、顺序访问，不主动制造封禁；
- HTTP 作为第一层，Firefox 作为动态页面兜底；
- 多 Agent 不直接运行脚本，而是通过 Collection API 使用数据；
- P0 先跑通真实采集核心，P1 再接 API，P2 再评估 Weknora 和浏览器 Skill 固化；
- 任何价格、库存、配送结论都必须带采集时间和区域上下文。
